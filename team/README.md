# FreeRTOS Chapter 3 — Examples 01~09 (STM32F429ZI)

Based on the nine examples in *Mastering the FreeRTOS Real Time Kernel*, Chapter 3. These are educational **STM32F429ZI register-level adaptations**, not byte-for-byte copies of the book's simulator examples. They preserve the Task count, relative priorities, blocking/delay behavior, and Task creation/deletion ideas. All nine files have their own `main()`, UART helper, and FreeRTOS includes (no shared project header).

| File | Book example | Core behavior |
| --- | --- | --- |
| `01_creating_tasks.c` | 1 | Two functions, same priority, busy waiting |
| `02_task_parameter.c` | 2 | One function, two instances, `pvParameters` |
| `03_experimenting_with_priorities.c` | 3 | Priority 1 vs 2, lower task starvation |
| `04_blocked_state_delay.c` | 4 | `vTaskDelay(250ms)` enables lower priority task |
| `05_delay_until.c` | 5 | `vTaskDelayUntil(250ms)` periodic reference |
| `06_blocking_and_nonblocking.c` | 6 | Two continuous P1 + periodic P2 (3ms) |
| `07_idle_task_hook.c` | 7 | Count Idle Hook calls while tasks block |
| `08_changing_task_priorities.c` | 8 | Task1 P2 raises Task2 P1→P3; Task2 lowers P3→P1 |
| `09_deleting_tasks.c` | 9 | P1 creates P2, P2 self-deletes, Idle reclaims |

## Build and run

1. Use one `.c` at a time as your application's `main.c`; **never compile all nine together** because each defines its own `main()`.
2. Ensure the existing project already includes FreeRTOS kernel, Cortex-M4F port, heap implementation (`heap_4.c` or equivalent), Startup and Linker configuration, and valid SVC/PendSV/SysTick handlers. In CubeMX/CubeIDE, avoid duplicating `main`/handler functions or having additional generated task code unintentionally started.
3. **UART logging assumes APB1 PCLK1=16MHz** and configures USART3 TX on PD8, AF7, 115200 8N1 (ST-LINK VCP on NUCLEO-F429ZI). If your project sets APB1 to another clock (e.g. PLL-based `SystemClock_Config()`), adjust USART3 BRR accordingly; otherwise text will be garbled. Default reset HSI/PCLK1=16MHz matches this demonstration, if no clock reconfiguration happened.
4. The example sources use `configUSE_PREEMPTION=1`, `configUSE_TIME_SLICING=1`, `configTICK_RATE_HZ=1000` (matching your posted FreeRTOSConfig.h's effective settings). Required: `INCLUDE_vTaskDelay`, `INCLUDE_vTaskDelayUntil`, `INCLUDE_vTaskPrioritySet`, `INCLUDE_uxTaskPriorityGet`, `INCLUDE_vTaskDelete` as appropriate.
5. **Example 7 only:** change `#define configUSE_IDLE_HOOK 0` to `1` in `FreeRTOSConfig.h`; do not define `vApplicationIdleHook()` elsewhere at the same time.
6. Your configuration includes `configSUPPORT_STATIC_ALLOCATION=1`: your FreeRTOS project must provide `vApplicationGetIdleTaskMemory()` (and relevant Timer Task static hooks where applicable), normally generated by STM32CubeMX. The `.c` files rely on your existing project implementation of these kernel hooks.
7. Serial writes have brief per-character critical sections to protect TXE/DR register accesses; two tasks can still interleave characters or lines. This may introduce latency and affects exact 3ms timing, so **Example 6 UART output is conceptual, not timing evidence**. For timing analysis, use GPIO + logic analyzer or DWT cycle counter instead of text output.
8. To use GDB: set breakpoint on `vTaskSwitchContext`, inspect `pxCurrentTCB`; break at `vTaskDelete` and `prvCheckTasksWaitingTermination` for Example 9 (internal names version-dependent).

These are teaching examples, not production-grade UART synchronization, timing measurement, or CubeMX-generated full firmware. The 2016 book uses `vPrintString` on a simulator and uses its own null-loop delays; USART register setup and reduced stack depths here are STM32 adaptations.
